Code-defined workflows are registered on each host. Published workflows travel as verified bundles: a host fetches a bundle by its digest, checks it and loads it into its own collectible context. This page covers versions, packages, native libraries, the cache, limits and unloading.

## Versions and structure

Workflow versions and draft definitions are stored in the selected repository. Code-defined executable definitions are registered locally on each host that may run them. Published versions are fetched by their immutable bundle digest when bundle hosting is enabled. Workflow identity is the declared `(name, version)`; names are required. A compiler-free `StructureHash` checks checkpoint compatibility and refuses changed structure at registration, start, resume, recovery and child resolution. It includes ordered steps, types, waits, joins, combiners, loops, handlers, children and expression shapes; it ignores delegate bodies, captured values and presentation metadata. Change the version when changing behavior. See [identity and expressions](fluent-api.md#identity-and-expressions). Checkpoint schema 1 (`ixiflow-1`) is a one-time break: older saved instances are refused without migration; reset development state and restart hosts together.

The checkpoint contract and structure-hash format are 1, with runtime marker `ixiflow-1`; pre-release checkpoints are refused. Bundle manifests use format 6 and host/executor messages use contract 14.

## Enabling bundles

Enable published workflows by calling `UseWorkflowBundles(cacheDirectory, maxCachedBundles: 16)` on the builder returned by `AddIxIFlow()`. The selected repository's artifact table is used by default; `UseFileSystemArtifacts` can replace it. Start a published version with `client.StartAsync("Approval", version: 1, workflowData: data)`.

A configured bundle host advertises `bundle-host` and compatible catalog workflow/version structure hashes. Capabilities refresh on heartbeats and local catalog changes. An unmet workflow demand also triggers a refresh, at most once per heartbeat interval; a failed refresh leaves the demand unmet and hands execution off. A published start saves both demands and its `BundleDigest`; recovery and child instances use their own saved pins. Downloads and cached archives are verified before loading, and shared assembly identities/versions must match the manifest's compatibility profile. The runtime set comes from framework deps files in `APP_CONTEXT_DEPS_FILES`, or only `runtimepack.*` libraries in the application's deps file for self-contained deployments, including ASP.NET. Application assemblies remain private even beside runtime DLLs or under a directory named `shared`. Unreadable runtime metadata disables bundle compatibility without failing host startup. Self-contained single-file processes expose no runtime manifest, so they can neither host nor publish bundles: such a host logs a warning and does not advertise `bundle-host`, and publishing from one fails with `PUB008`. The profile declares only runtime/SDK assemblies referenced by the workflow and its private closure, plus CoreLib and the runtime facade. Private dependencies come only from verified archive entries.

## Packages and NuGet resolution

`WorkflowPublisher.UploadPackageAsync(stream)` accepts a `.nupkg` and registers its immutable identity, digest and extracted activity descriptors. It returns the audited `PackageRegistration` (`Stored`, `Activities`, `Created`). The typed publisher, full no-write validation and durable attempt service are documented in [Authoring](../src/IxIFlow.Authoring/README.md). `WorkflowPublisher.ReadPackageAsync` and `StorePackageAsync` expose bounded candidate verification and audited storage as separate calls. Offline uploads can arrive before their dependencies and remain Pending until indexing completes. See the [activity and package catalog](activity-catalog.md) for receipts, scopes, Local providers and the indexing service. Set `WorkflowPublisherOptions.NuGetConfigPath` to a standard `NuGet.Config` for feeds; NuGet handles its source credentials, and the catalog stores no feed secrets. Publishing resolves `imports.catalogs` and their transitive closure for `TargetFramework` (default `net10.0`), compiles against NuGet-selected reference assemblies, validates activity markers and mappings, and pins exact package identities, digests, entry hashes and runtime assets. Unversioned imports select the highest stable version and are rewritten as exact imports. Packages remain separate artifacts and are retained while any published version or saved instance needs them.

Hosts fetch package artifacts only by their published digests and load managed assemblies into the bundle's own context. Native assets are selected at publish using NuGet's portable RID graph and package runtime graphs; each host loads its recorded RID set. A host without a compatible set omits that workflow version from its capabilities. Hosts require no feed configuration or NuGet client libraries.

Resolution reads uploaded dependency groups from the catalog and bounded remote nuspecs before downloading selected archives. HTTP feeds must expose a NuGet V3 service index with PackageBaseAddress. HTTP discovery (service index and version lists) is bounded too; remote candidate discovery never downloads nupkg files. Selected transfers stream directly into a bounded seekable destination, charging the aggregate budget during transfer, including retries. Historical collected identities do not consume the available-candidate budget. `MaxPackageCandidates`, `MaxResolvedPackages` and `MaxPackageResolutionBytes` bound the work, alongside `PackageReadLimits`. Configured feeds use direct downloads without NuGet's user HTTP cache. Authentication providers are discovered through NuGet and requested non-interactively when a source challenges; credentials and HTTP resources are owned and disposed by each resolution. Uploads-only resolution does not acquire the global NuGet credential gate. A configured `NuGet.Config` must exist.

## Native libraries

Native imports are inspected at publish and again at load: every non-system import must be declared in the applicable RID closure. Windows loads use only the declared library directory and System32 (`LOAD_LIBRARY_SEARCH_DLL_LOAD_DIR | LOAD_LIBRARY_SEARCH_SYSTEM32`). On Linux, declared dependencies are preloaded by SONAME from verified open descriptors (`/proc/self/fd/N`), and OS dependencies are preloaded by absolute paths in system library directories. Undeclared P/Invoke names without path separators may resolve only to OS system libraries; the current directory, `PATH`, environment library search paths, and the bundle cache are never fallback locations. ELF dependencies must carry the imported SONAME; ELF search directives may name only `$ORIGIN`/`${ORIGIN}`, and cyclic declared imports and loader filters are refused. Other Unix hosts load re-verified copies from a freshly created owner-only private directory. Native module references and verification handles remain owned until the collectible context is collected, including after a failed load or retirement request.

Native libraries are materialized as a complete declared set under the bundle's cross-process digest lock, checked for unexpected entries and links, verified with bounded reads, and loaded eagerly. `FetchTimeout` applies separately to each artifact. If retention cannot read an orphan instance bundle, it reports `ixiflow.artifact.retention.unreadable_pin`, preserves registered package content conservatively, and continues collecting unrelated abandoned bundles.

## Cache and trust

The configured cache root, its resolved parent path, the host process (including libraries injected before startup), and OS library directories are administrator-controlled trust boundaries. Other identities must not have write access to them. The host permits linked ancestors and resolves the configured root once; it refuses links below that root. Under the bounded per-digest lock it removes unexpected/stale temporary entries, replaces length/hash mismatches, and re-materializes pinned bytes. Windows deny-write handles remain open through the usable context lifetime; Linux loads use the verified inode rather than reopening its pathname. Other Unix platforms create an owner-only private directory for each load in the host process, verify and eagerly load its copies, then unlink the copies and remove the directory in finally, including after a partial load. Native mappings remain usable after unlink. Missing cleanup entries count as already removed; other cleanup errors are logged and cannot fail a successful load. A crash can leave a private directory for the operating system's temporary-file cleanup. Cache lock expiry reports `ArtifactUnavailable`.

Each digest has its own collectible load context. `maxCachedBundles` bounds the loaded-context cache; active operations, queued starts and activity tasks retain leases until they finish. Set it to zero to release a context after its last operation. Loaded contexts are reused without rereading disk. Cache files contain whole verified archives and are written atomically under a per-digest process lock, so hosts can share a directory; archive disk usage is managed separately from the loaded-context bound. The cache directory must be trusted: grant write access only to the hosts that use it. A corrupt cache entry, including an oversized file with the wrong digest, is rejected before loading with `ArtifactMismatch` and removed; a later operation can fetch it again. Cache write failures still allow verified downloads to run. Missing/download failures use `ArtifactUnavailable`. Both interrupt execution and keep the committed checkpoint.

## Limits

The `UseWorkflowBundles(WorkflowBundleOptions)` overload configures `FetchTimeout` and `CacheLockTimeout` (each 30 seconds by default) and `ReadLimits`: maximum archive bytes (64 MiB), manifest bytes (1 MiB), entry count (1,024, including the manifest), bytes per other entry (32 MiB), and total expanded bytes (256 MiB). Reads enforce these bounds while streaming and before expanding entries. Caller cancellation propagates as cancellation. Cache-lock waiting has its own cancellable deadline; on expiry the host bypasses the cache and downloads verified bytes. Only downloading and verification consume the fetch budget. Fetch timeouts and independent artifact-store cancellation are `ArtifactUnavailable` interruptions and preserve the checkpoint. Archive limits report `ResourceExhausted` and leave digest-valid cached archives intact. An inspection GET that hits a bundle read limit returns HTTP 503 naming the bundle limit.

## Unloading

Unloading is cooperative: a static field, event handler, delegate, `Type`, or returned data object holding a bundle type keeps that context loaded. Runtime serializer caches can also delay collection briefly. Engine reflection caches use weak ownership and serializer profiles are scoped to their load context. Saved data/event/value type names use the recursive `ixi-type:1:` format; recreate earlier development databases and republish earlier bundles rather than migrating their type names.
